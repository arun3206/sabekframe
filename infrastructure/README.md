# Yaadon AWS infrastructure

This AWS CDK application defines the private upload-storage foundation. The CDK source remains in this repository; it is not manually uploaded to the AWS Console. During deployment, CDK synthesizes CloudFormation and submits it to AWS using temporary IAM Identity Center credentials.

## What each environment stack creates

- One private S3 bucket for short-lived raw uploads.
- One private S3 bucket for sanitized photographs.
- S3 bucket policies that reject non-HTTPS access.
- S3-managed encryption, ACLs disabled, and every public-access mechanism blocked.
- Sanitized uploads expire after one day and generated outputs after seven days;
  server-controlled master templates under `templates/` are retained.
- CORS restricted to `http://localhost:3000` for development.
- One on-demand DynamoDB table for upload ownership, expiry, idempotent results, and rate limits.
- DynamoDB TTL and one-day S3 lifecycle backstops.
- An hourly Lambda triggered by EventBridge to enforce configured upload retention.
- One-week CloudWatch retention for cleanup logs without photo bytes or object keys.
- A native image-finalization Lambda that runs Sharp outside the Cloudflare runtime.
- A Secrets Manager secret for server-only provider API keys.
- In production, a resource-scoped IAM workload user for the Cloudflare Worker.

Resource names are generated by CloudFormation to avoid collisions. Both buckets and the DynamoDB table are retained if the stack is deleted, so an accidental `cdk destroy` cannot erase customer state.

## 1. Configure AWS CLI access

Install AWS CLI v2, then configure the IAM Identity Center profile:

```powershell
aws configure sso --profile arun-admin
aws sso login --profile arun-admin
aws sts get-caller-identity --profile arun-admin
```

The final command should show the intended AWS account. Do not proceed if it shows a different account.

## 2. Install and inspect locally

From the project root:

```powershell
pnpm install
pnpm infra:synth
```

`infra:synth` is local and creates no AWS resources.

## 3. Bootstrap CDK once

Replace `YOUR_12_DIGIT_ACCOUNT_ID` with the account shown by the identity check:

```powershell
.\node_modules\.bin\cdk.cmd bootstrap aws://YOUR_12_DIGIT_ACCOUNT_ID/ap-south-1 --profile arun-admin
```

Bootstrapping creates the standard CDK deployment resources in the Mumbai region. It is required once per account and region.

## 4. Review and deploy development storage

Set the temporary profile for the current PowerShell window:

```powershell
$env:AWS_PROFILE = "arun-admin"
pnpm infra:diff
pnpm infra:deploy:dev
```

Review the `diff` before deploying. CDK asks for approval if a deployment broadens IAM or security permissions. After deployment, CloudFormation outputs the generated raw bucket, sanitized bucket, and upload-state table names.

For local AWS testing, copy `.env.example` to `.env.local`, set `UPLOAD_STORAGE_PROVIDER=aws` and `RATE_LIMIT_PROVIDER=dynamodb`, then copy the three CloudFormation output names into the corresponding AWS variables. Export the signed-in profile's temporary credentials into the PowerShell process that starts Next.js; never copy SSO cache contents or access keys into the environment file:

```powershell
$awsSession = aws configure export-credentials --profile arun-admin | ConvertFrom-Json
$env:AWS_ACCESS_KEY_ID = $awsSession.AccessKeyId
$env:AWS_SECRET_ACCESS_KEY = $awsSession.SecretAccessKey
$env:AWS_SESSION_TOKEN = $awsSession.SessionToken
```

## Production

The production stack is deployed in AWS account `867982505694`, Mumbai (`ap-south-1`).
Its S3 CORS configuration allows `https://cherishkit.com`, `https://www.cherishkit.com`,
and the Cloudflare `workers.dev` fallback. Review and update it with:

```powershell
$env:AWS_PROFILE = "arun-admin"
aws sts get-caller-identity
pnpm infra:diff:production
pnpm infra:deploy:production
```

The production deployment command also uploads and verifies the Mother & Little Radha
generation master at its fixed private S3 key. It resolves the retained sanitized bucket
from the production CloudFormation stack output and never makes the bucket public.

The production stack has termination protection, retains both S3 buckets and DynamoDB,
and restricts upload CORS to the deployed Cloudflare origin. OpenAI and Magic Hour keys
are stored in `yaadon/production/provider-api-keys`; do not duplicate them in Cloudflare.
Razorpay Test Mode credentials are stored separately in
`ai-photo-generator/razorpay/test` as `RAZORPAY_KEY_ID` and
`RAZORPAY_KEY_SECRET`. The production stack also creates
`ai-photo-generator/razorpay/live`; populate it with `RAZORPAY_KEY_ID`,
`RAZORPAY_KEY_SECRET`, and a distinct `RAZORPAY_WEBHOOK_SECRET`. Select the secret with
`AWS_RAZORPAY_SECRET_ID` and set `RAZORPAY_MODE` to the matching `TEST` or `LIVE` mode.

The IAM user `yaadon-production-cloudflare-worker` intentionally has no console password
or access key in CloudFormation. Create one access key only when configuring Cloudflare,
save it directly as the encrypted Worker secrets `AWS_ACCESS_KEY_ID` and
`AWS_SECRET_ACCESS_KEY`, and rotate/delete it if it is ever exposed. All other production
resource names are committed as non-secret Wrangler variables.
